All required Week 3 tasks were completed. The application now provides arole-protected ticket management interface backed by Laravel, MySQL, LaravelSanctum, and React.

Ticket CRUD

Create

Employees and Admins can create tickets with:

Description

Priority

Read

The frontend provides:

Paginated ticket list

Ticket-details page

Ticket number

Subject and description

Category and priority

Current status

Assigned Support Agent

Exact creation date and time

Latest assignment date and time

SLA due date and overdue indicator

Update

An Employee can update their own ticket only while its status is Open.

Once the ticket is assigned or work begins, it becomes read-only for theEmployee.

Admin retains emergency override access.

Delete

An Employee can delete their own ticket only while it is Open.

Admin retains override access.

Managers and Support Agents cannot delete tickets.

Categories and Priorities

Authenticated users can retrieve ticket categories and priorities from thebackend. The Create and Edit forms use these lookup APIs instead of hard-codedcategory IDs.

The category filter was corrected so the React frontend and Laravel backendboth use categoryId.

SLA Due Dates

The system automatically calculates a deadline when a ticket is created:

Priority

Resolution deadline

Urgent/Critical

4 hours

High

1 day

Medium

3 days

Low

5 days

Existing tickets were backfilled through database migrations. Open tickets thatpass their deadline display an Overdue indicator. Changing the priority of anOpen ticket recalculates its deadline from the original creation time.

Role-Based Permissions

Employee

Create tickets.

View only their own tickets.

Edit or delete their own Open tickets.

View public comments on their own tickets.

Cannot view internal staff notes.

Cannot edit or delete after assignment or work begins.

Support Agent

View only tickets assigned to them.

Cannot edit or delete the original ticket.

Cannot access tickets assigned to another Agent.

Workflow actions and staff discussions are extended in Week 4.

Manager

View and monitor all tickets.

Search, filter, sort, and paginate tickets.

View recent tickets and workload/report totals.

Ticket assignment interface is completed in Week 4.

Admin

View all tickets.

Create, edit, and delete tickets with override access.

Access the dashboard and administrative backend endpoints.

Security and Privacy Corrections

Employees cannot see internal Agent comments.

Employees cannot create internal notes.

Unassigned Support Agents cannot access another ticket's comments.

Closed-ticket comments cannot be created, edited, or deleted.

Support Agents receive only their assigned tickets from the ticket-list API.

Invalid role and ownership operations return authorization errors.

Database Changes

Added nullable dueAt datetime field to tickets.

Added dueAt to the Ticket model's fillable and datetime-cast fields.

Backfilled deadlines for existing tickets.

Added the latest assignment timestamp to ticket-list API responses asassignedAt.
