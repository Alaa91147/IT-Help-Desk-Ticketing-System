# Ticket Management APIs

--------------------------------------------

## Get All Tickets

* **GET** /api/tickets

Returns tickets with related information:

* Ticket creator
* Assigned Support Agent
* Category
* Priority
* Status

Visibility is controlled by role:

* Employee sees their own tickets
* Support Agent sees assigned tickets and Open/Closed tickets for history tracking
* Manager sees all tickets
* Admin sees all tickets

Features:

* Keyword search
* Filtering
* Sorting
* Pagination
* Exact-date filtering
* Date-range filtering

--------------------------------------------

## Get Single Ticket

* **GET** /api/tickets/{ticket}

Returns the details of a specific ticket.

Authorization:

* Ticket owners can view their own tickets
* Assigned Support Agents can view assigned tickets
* Managers and Admins can view all tickets
* Unauthorized requests return HTTP 403 Forbidden

--------------------------------------------

## Create Ticket

* **POST** /api/tickets

Creates a new ticket.

Features:

* Generates a unique ticket number
* Assigns the logged-in Employee or Admin as owner
* Sets the default status to Open
* Validates category, priority, subject, and description

--------------------------------------------

## Update Ticket

* **PUT** /api/tickets/{ticket}

Updates:

* Subject
* Description
* Category
* Priority

An Employee can update their own ticket only
while its status is Open. Admin retains override
access.

--------------------------------------------

## Delete Ticket

* **DELETE** /api/tickets/{ticket}

An Employee can delete their own ticket only
while it is Open. Admin retains override access.

--------------------------------------------

## Assign Ticket

* **PATCH** /api/tickets/{ticket}/assign

Allows Managers and Admins to assign or reassign
tickets to active Support Agents.

The operation:

* Validates that the selected user is an active Support Agent
* Changes ticket status to Assigned
* Records who assigned the ticket
* Records the assignment date and time

--------------------------------------------

## Start Ticket

* **PATCH** /api/tickets/{ticket}/start

Allows only the assigned Support Agent to start
working on an Assigned ticket.

Changes the ticket status to InProgress.

--------------------------------------------

## Resolve Ticket

* **PATCH** /api/tickets/{ticket}/resolve

Allows the assigned Support Agent or Admin to
resolve an InProgress ticket.

Changes the status to Resolved and saves the
resolution date and time.

--------------------------------------------

## Close Ticket

* **PATCH** /api/tickets/{ticket}/close

Allows Admin to close a Resolved ticket.

Changes the status to Closed and saves the
closing date and time.

--------------------------------------------

# Ticket Workflow

Open

↓

Assigned

↓

InProgress

↓

Resolved

↓

Closed

Invalid workflow transitions are rejected.

--------------------------------------------

# Role-Based Access Control

## Admin

* Full ticket access
* Create, view, update, and delete tickets
* Assign and reassign tickets
* Resolve and close tickets
* Activate and deactivate users
* Change user roles
* Manage categories and priorities
* Access reports

--------------------------------------------

## Manager

* View and monitor all tickets
* Search, filter, sort, and paginate tickets
* View active Support Agents
* Assign and reassign tickets
* View ticket reports
* Monitor Support Agent workload

--------------------------------------------

## IT Support Agent


* View assigned tickets
* View Open and Closed tickets for history tracking
* Start assigned tickets
* Resolve assigned tickets
* Add public and private comments
* View private comments on assigned tickets
* Upload attachments
* Cannot work on another agent's ticket

--------------------------------------------

## Employee


* Create tickets
* View and track their own tickets
* Edit or delete their own Open tickets
* Add public comments and attachments to their own tickets
* View public and private comments on their own tickets
* Cannot edit or delete after the ticket is assigned
--------------------------------------------

## Get Ticket Comments

* **GET** /api/tickets/{ticket}/comments

Returns all comments for the selected ticket.

Authorization:

* Ticket owners can view comments on their own tickets
* Assigned Support Agents can view comments on assigned tickets
* Unassigned Support Agents cannot view comments
* Private comments are visible to the ticket owner and assigned Support Agent
* Unauthorized requests return HTTP 403 Forbidden

--------------------------------------------

## Create Ticket Comment

* **POST** /api/tickets/{ticket}/comments

Creates a new comment for the selected ticket.

Authorization:

* Ticket owners can create public comments
* Assigned Support Agents can create public and private comments
* Support Agents cannot comment on tickets that are not assigned to them
* Unauthorized requests return HTTP 403 Forbidden

--------------------------------------------

## Update Ticket Comment

* **PATCH** /api/tickets/{ticket}/comments/{comment}

The comment author can update their own comment.
Admin retains override access.

--------------------------------------------

## Delete Ticket Comment

* **DELETE** /api/tickets/{ticket}/comments/{comment}

The comment author can delete their own comment.
Admin retains override access.

Features:

* Ticket-level authorization
* Public and private comments
* Ticket owners can create public comments
* Assigned Support Agents can create public and private comments
* Private comments are restricted to authorized users
* Author/Admin update and deletion permissions
* Closed-ticket protection

--------------------------------------------

# Ticket Attachments

* **GET** /api/tickets/{ticket}/attachments
* **POST** /api/tickets/{ticket}/attachments
* **GET** /api/tickets/{ticket}/attachments/{attachment}/download
* **DELETE** /api/tickets/{ticket}/attachments/{attachment}

Features:

* Secure upload and download
* Maximum file size of 10 MB
* PDF, DOC, DOCX, PNG, JPG, JPEG, and TXT support
* Ticket-level authorization
* Uploader/Admin deletion permissions
* Stored-file cleanup after deletion

# Category, Priority, and Status APIs

Authenticated lookup APIs:

* **GET** /api/categories
* **GET** /api/priorities
* **GET** /api/statuses

Admin management:

* Create, update, and delete categories
* Create, update, and delete priorities
* Prevent deletion of values already used by tickets

Workflow statuses are read-only because changing
their names would break ticket transitions.

* Tickets grouped by priority
* Assigned-ticket count by Support Agent
* InProgress-ticket count by Support Agent
* Resolved/Closed-ticket count by Support Agent

# Database Naming

The custom database schema follows the required
naming convention:

* Every custom table has id as its primary key
* Custom foreign keys use camelCase without underscores
* Examples: roleId, userId, ticketId, categoryId,
  priorityId, statusId, assignedUserId,
  assignedByUserId, and uploadedByUserId
* Custom timestamps use createdAt and updatedAt
* Laravel internal fields retain Laravel's required names
